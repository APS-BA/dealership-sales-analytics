## 1. BETTER ANALYST

**What it is.** A commercial agentic AI data-analysis platform. The user
supplies data and a natural-language brief; the platform writes and executes
Python in its own sandbox and returns generated files.

**How it was used.** The three raw GST registers were uploaded and given a
single detailed brief specifying the preprocessing rules, all four analyses
(A: category and seasonality; B: market basket; C: seasonal pricing; D: RFM)
and the required workbook structure.

**What it generated.**
- 437 lines of Python (preprocessing + Analyses A–D + workbook build)
- `lg_kent_marketing_analytics_fy23_26.xlsx` — workbook v1
- 64 further lines of Python when asked to print result tables
- `lg_kent_marketing_analytics_fy23_26_line_revenue_corrected_v2.xlsx` — v2

**Libraries it used** (visible in its generated source):
`pathlib`, `datetime`, `itertools.combinations`, `math`, `re`, `json`, `os`,
`pandas`, `numpy`, `openpyxl` (`Workbook`, `styles`, `utils`,
`formatting.rule.ColorScaleRule`).

**A material error it made, and how it was caught.**

Its first output computed category revenue by attributing each invoice's
`GRANDAMOUNT` to every category on that invoice. The relevant line from its
generated source:

```python
cat_fy = raw.groupby(["CATEGORY", "FISCAL_YEAR"], dropna=False)["GRANDAMOUNT_clean"] \
            .agg(lambda s: pd.to_numeric(s, errors="coerce").drop_duplicates().sum())
```

Because `GRANDAMOUNT` is an invoice-level total and `CATEGORY` is a line-level
attribute, this double-counts every multi-category invoice — and 40–43% of
invoices carry multiple lines.

The error was caught by a reconciliation test. For FY2023-24 it reported
Other 122,881,779 + Air Conditioner 103,528,590 + Television 124,299,138 +
Refrigerator 121,339,682 = **472,049,189**, against a true year total of
**435,000,673**, with three categories still unlisted. A decomposition whose
parts exceed its whole is definitionally wrong.

Consequence: it ranked Air Conditioner **third-largest and declining −9.5%**,
when AC is in fact the **largest category and the only growing one (+7.5%)**.
This would have inverted the central finding of the study.

It was sent back with the corrected basis
(`LINE_REVENUE = TOTAL + CGSTAMT + SGSTAMT + IGSTAMT`) and explicit
verification targets. Its v2 output then reconciled correctly:

```
FY2023-24: 435,457,080.65 / 435,000,673 = 1.001049
FY2024-25: 375,665,606.20 / 375,354,090 = 1.000830
FY2025-26: 410,428,892.22 / 410,127,123 = 1.000736
```

**Files:** `code/better_analyst/generated_code_v1.txt` (its actual source),
`code/better_analyst/session_notes.md` (brief, outputs, correction exchange).

**Reliability note.** Its workbook builder subsequently failed four consecutive
times when asked to regenerate with additional sheets, each attempt ending
"the spreadsheet request stalled before producing a workbook file." The final
submitted workbook was therefore generated by our own Python
(`code/build_workbook.py`), which reproduces and extends the corrected v2.

## 2–4. PYTHON, PANDAS/NUMPY, OPENPYXL

**Role.** The authoritative analysis. Every figure in the report and the deck
is produced by this code, which was also used to independently verify Better
Analyst's output — which is how both errors were detected.

**Files.**
- `code/analysis.py` — reproduces the entire analysis and prints every figure
  quoted in the report. Contains two runtime assertions: that `GRANDAMOUNT` is
  constant within each invoice, and that line revenue reconciles to invoice
  totals within ±1%. The run halts if either fails.
- `code/build_workbook.py` — builds the 17-sheet workbook.
- `code/requirements.txt` — pinned dependencies.
- `code/RUN_LOG.txt` — console output of a verified end-to-end run.

**To reproduce:** `pip install -r requirements.txt` then `python analysis.py`.
The scripts locate the raw registers automatically. Runtime ~2–3 minutes.

**Second error found by this code.** Monthly completeness testing revealed that
February FY2024-25 holds 298 invoices and March only 35, against ~800 and
~1,100 in adjacent years — roughly ₹56.7m of missing billing. This manufactured
the apparent "collapse and recovery" (−13.7%, +9.3%). On the like-for-like
April–January window the business declined 1.3% then 6.6%: a steady 7.9%
erosion, with no collapse and no recovery. This changed the study's conclusion.
